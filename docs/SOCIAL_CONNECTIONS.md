# Social account connections

The workspace stores one connection per brand and provider account. The system never collects a user's social password. OAuth provider client credentials stay in server environment variables. User access and refresh tokens are stored as AES-256-GCM ciphertext in `social_profile_credentials`; the encryption key must be a random 32-byte hex value supplied as `SOCIAL_TOKEN_ENCRYPTION_KEY` and kept outside the database. Do not rotate this key without first adding a versioned key ring and re-encryption job.

OAuth state is single-use, expires after ten minutes, is stored only as a SHA-256 PKCE challenge, and is scoped to the organization, brand, user and platform. PKCE verifiers and OIDC nonces are encrypted. The callback checks the authenticated user and active organization again. Provider calls have a ten-second timeout, reject redirects, avoid caching and cap parsed responses at 64 KiB.

The scheduler should pass only the organization and social profile identifiers to jobs. Its server-side publisher may use `getValidSocialAccessToken` to load or refresh credentials. Never put bearer tokens in queue messages, browser responses, or logs. A publish timeout or missing post ID is recorded as indeterminate and requires operator review; automatic retry could create a duplicate post. Instagram publication saves its media-container ID before the final publish call. The worker checks that exact container and automatically marks the post published only when Meta reports PUBLISHED; other responses remain indeterminate for manual review. Facebook, Threads, and LinkedIn lack a persisted publish reference in the current flow and remain manual-only. A workspace manager can record the verified outcome, evidence, and provider post ID when published. Confirming that no post exists can either close the content as failed or authorize one manual retry; the retry requires a separate confirmation and evidence and returns the same approved job to the queue. Invalid or expired grants mark the connection for reauthorization. Instagram and Threads long-lived tokens can be refreshed using their current access token. Facebook Page tokens are stored encrypted and conservatively expire with the exchanged user token, so reconnect when they expire. LinkedIn programmatic refresh depends on partner approval; X, Google, TikTok and Pinterest refresh behavior depends on the granted app and token scopes. Disconnect deletes the local credential and disables only the selected account; provider-side grants are not revoked by this operation, so users may also revoke access in the provider's account settings.

## Provider setup

Set each provider's client ID and secret in the deployment environment. Meta uses one app pair for Facebook, Instagram and Threads. Add the exact callback URL `STUDIO_PUBLIC_ORIGIN/api/social-connections/callback` to every provider app. Production callback URLs must use HTTPS. For local development, use an HTTPS tunnel when a provider rejects localhost or HTTP callbacks. The web process needs OAuth credentials for connection flows; the supervised social publishing worker needs the LinkedIn client credentials, token encryption key, database URL, and publishing configuration.

| Provider | Environment variables | Initial identity scopes |
| --- | --- | --- |
| LinkedIn | `LINKEDIN_CLIENT_ID`, `LINKEDIN_CLIENT_SECRET`, `LINKEDIN_API_VERSION` | `openid profile w_member_social` for publishing |
| Instagram, Facebook, Threads | `META_CLIENT_ID`, `META_CLIENT_SECRET`, `META_GRAPH_API_VERSION` | Instagram Login: `instagram_business_basic`, `instagram_business_content_publish`; Facebook Pages: `pages_show_list`, `pages_read_engagement`, `pages_manage_posts`; Threads: `threads_basic`, `threads_content_publish` |
| TikTok | `TIKTOK_CLIENT_KEY`, `TIKTOK_CLIENT_SECRET` | `user.info.basic` |
| X | `X_CLIENT_ID`, `X_CLIENT_SECRET` | `users.read offline.access` |
| YouTube | `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | `youtube.readonly` |
| Pinterest | `PINTEREST_CLIENT_ID`, `PINTEREST_CLIENT_SECRET` | `user_accounts:read` |

The common protocol layer is `oauth4webapi` (MIT, zero runtime dependencies); provider adapters keep endpoint, scope, account lookup and token-refresh behavior separate. Facebook OAuth enumerates the Pages where the user has the `CREATE_CONTENT` or `MANAGE` task and stores each Page token encrypted. When a post is submitted for approval, the user selects its connected destination profile; that profile is included in the approval fingerprint and revalidated before publication. Instagram uses Instagram Login for professional accounts and publishes one approved feed image plus caption. Before approval, the app checks JPEG/PNG/WebP source type, file size and aspect ratio; at publish time it converts the image to sRGB JPEG, limits the output width and size, checks Meta's current publishing quota, and stages it temporarily in the same private S3 bucket. Meta receives a one-hour presigned URL; no bucket-wide public access is needed. The configured production S3 endpoint must be publicly reachable over HTTPS for Meta's media fetch; LocalStack is only suitable for local flow checks. Staging objects are removed after a definite publish outcome and leftovers older than 24 hours are removed when that tenant next publishes. Give that worker S3 GetObject, PutObject, DeleteObject and ListBucket access for the configured bucket. Meta app review and Advanced Access may be required for external customers; the app's Development mode only supports app-role accounts. Facebook currently publishes text posts. Instagram currently publishes single-image feed posts; Reels, Stories, carousels and video remain unsupported. Some Instagram accounts may also require Page Publishing Authorization. TikTok public posting and LinkedIn program access can require provider approval. A connection alone does not mean every scheduled post type is publishable.
# Scheduled publishing

LinkedIn text posts now use the native Posts API through a dedicated server adapter. Requesting approval binds the approval snapshot to the explicitly selected connected LinkedIn profile with the `w_member_social` scope. Final approval inserts a tenant-scoped, unique publication job in the same database transaction. The background process rechecks tenant, brand, profile health, approval status, exact fingerprint, latest content version, and text-only support before it sends anything.

Run `npm run worker:social-publishing` as a separately supervised process after applying the Drizzle migrations. It exits unless `SOCIAL_PUBLISHING_ENABLED=true`. The web process uses the same flag to distinguish a deliberately disabled worker from a missing or stale heartbeat; production deployments must configure the flag consistently for both processes. The worker reports a heartbeat every 30 seconds and the dashboard marks it stale after 90 seconds. Dashboard queue counts remain scoped to the active tenant, brand, and network filters and include only jobs whose scheduled attempt is due. Configure `LINKEDIN_API_VERSION` to a currently supported `YYYYMM` version and enable the LinkedIn Share on LinkedIn product for the app. Existing LinkedIn connections must reconnect to grant `w_member_social`. The worker stores external post IDs and attempt outcomes, never access tokens in job rows. A timeout, missing provider post ID, or expired worker lease becomes `indeterminate` and is not retried automatically because the provider may already have created the post. Workspace managers can resolve an indeterminate job in the calendar after verifying the destination account; that action records evidence and the external ID when available. The calendar shows the publication state and polls while due work is active.

LinkedIn and Facebook support text-only posts through registered platform adapters. Threads supports text posts capped at 500 characters. Instagram supports one approved JPEG-converted image with a caption capped at 2,200 characters. Facebook Pages require the Page publishing tasks and permissions listed above. Existing Meta connections must reconnect to grant publishing permissions. Set `META_GRAPH_API_VERSION` to a currently supported Graph API version (the example uses `v27.0`). Rejections become failed jobs; ambiguous responses remain indeterminate and are never automatically retried. Other connected platforms remain connection-only until their publishing payloads, media pipelines, permission gates, and provider-specific retry rules are implemented.

## Engagement analytics

The Analytics screen can manually refresh up to ten recent, confirmed Facebook and Instagram publications per request. A post with a recent snapshot is skipped for one hour. Each collection is tenant-scoped and appended to `social_analytics_snapshots` with its collection status, source, definition version, collection time, and `post_lifetime` coverage. Results are aggregated separately per network because their counters have different definitions. A missing value stays unavailable rather than being reported as zero. The existing publishing worker does not poll engagement metrics in the background.

For Instagram, the collector reads the published media's `like_count` and `comments_count` using the Instagram Media endpoint with the existing `instagram_business_basic` permission. For Facebook, it reads reaction and comment `summary.total_count` and `shares.count` using the Graph API and existing `pages_read_engagement` permission. These are lifetime counters observed when the request runs, not counts attributed to the selected Analytics date range. The date range selects which publication jobs are eligible and aggregateable; it does not bound the provider's counter window. Instagram shares are not returned by this login mode.

Provider permission gaps are stored as `permission_denied`; invalid grants are stored as `authentication_required`; other provider/API failures are `unavailable`. No raw provider error bodies or access tokens are persisted. Reach, impressions, video views, saves, Threads, LinkedIn, and account-level time-series metrics remain unsupported in this slice. Meta's available Page Insights metrics can change by Graph API version and Page role; the collector deliberately avoids deprecated Page impression metrics.

References: [Instagram Media](https://developers.facebook.com/docs/instagram-platform/reference/instagram-media/), [Facebook Page Insights](https://developers.facebook.com/docs/graph-api/reference/insights/), [Facebook post reactions](https://developers.facebook.com/docs/graph-api/reference/post/reactions/).

Migration `0026` is additive and does not change existing publication or connection rows. Apply it before deploying the code that reads and writes snapshots. Rolling back the application leaves collected rows intact and unused; removing them requires a separate, explicitly reviewed migration.
