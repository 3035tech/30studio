# 30studio product context

Read this file together with the repository `AGENTS.md` before doing product work. `CLAUDE.md` and `.cursor/rules/30studio.mdc` direct their assistants to the same engineering rules.

## Product

**30studio** is a multi-tenant SaaS marketing workspace. It is one product built with Next.js, not a collection of separate marketing tools. It manages social connections, brand identity, research, content planning and production, media, review, human approval, scheduling, publication, and analytics in one interface.

## Multi-tenant account model

- A customer account is a tenant/organization.
- An organization can own many brands, such as 3035TECH, 30pay, 30grow, 30teach, a personal brand, or brands owned by another future customer.
- An organization can have multiple users. Memberships and invitations connect users to organizations; one user may be a member of multiple organizations.
- Tenant-owned data must be scoped to its organization. Brand-owned data must also reference a brand belonging to that same organization.
- No cross-tenant reads, writes, search, analytics, storage, AI context, logs, caches, or background jobs.
- Server-side authorization resolves the active tenant from a verified session and membership. Client/model/queue-supplied tenant identity is never authoritative.
- Start with explicit roles: owner, admin, editor, approver, and analyst. Roles and permissions are checked in server code for every action.
- Better Auth's organization plugin is the authentication/account provider. The active organization comes from the server-verified session, and each request rechecks its membership in PostgreSQL before doing tenant work. The first role mapping is maintained in application constants and mirrored into Better Auth's access-control plugin; unknown roles fail closed.

## Product decisions

- Core app and workflows live in 30studio. The current first-release recommendation is Next.js plus an internal worker process from this same repository; long-running jobs never run inside UI request handlers. Do not use n8n or Postiz as operational products or sources of truth.
- Social networks are external APIs; their native connectors are modules owned and surfaced by 30studio. Each connector declares its actual capabilities and restrictions.
- PostgreSQL is the source of truth. All application data access goes through Drizzle ORM; application code must not contain raw SQL.
- AI copy and image generation send the user-requested content context and approved Brand Kit to the configured provider. The first adapter is OpenAI via AI SDK; credentials and model IDs are server-only, text responses are requested with provider storage disabled, and copy is not persisted unless the user saves it. Image outputs are attached to an exact content version in private S3 storage and require separate human review. Provider privacy/retention terms, image rights, usage metering, and tenant disclosure remain operational review items.
- Portuguese (Brazil) and English are required from the first feature, using `next-intl` and localized message catalogs.
- Build reusable, branded UI components on accessible Radix primitives. Feature pages do not use raw browser controls or library defaults directly.
- The approved 30studio product identity is documented in `docs/PRODUCT_BRAND.md`. Use the supplied logos/icons, Sora + Inter fonts, and Tailwind CSS v4 theme; customer Brand Kits remain tenant-owned and separate.
- Content publication always requires server-verified human approval of the exact content and media version.

## Current implementation boundary

- Competitor collection and analysis are asynchronous. Persist source records, extracted observations, provenance, timestamps, and analysis in organization- and brand-scoped PostgreSQL tables; source archival preserves collected history. Tell users that first results may take a few minutes or longer. Use authorized social APIs and permitted public feeds/sites; social-page scraping is not a fallback for unavailable API access. See `docs/COMPETITOR_RESEARCH.md`.

- Better Auth user/session/account/verification, organization, member, and invitation tables are generated by its pinned CLI and included in Drizzle's schema.
- Brands and social-profile metadata have required organization ownership. Social profiles use a composite foreign key so a profile cannot point to a brand from another organization. API repositories require organization scope, and the auth helper checks the active membership and a named permission.
- A first login/signup and workspace/brand entry screen is implemented, including tenant-scoped brand creation, editing, and logical archiving. Team management includes email invitations, verified-email acceptance, role changes/removal, and audit history. SMTP credentials still need to be configured for real email delivery. Docker development seeds a verified demo owner so local UI exploration does not depend on SMTP.
- The `feature/editorial-calendar` branch adds a tenant-scoped editorial calendar with month/list views, filters, and local-time display. A campaign stores the brand-level topic/brief and creates one independently scheduled content item per selected social network. Each item can append immutable canonical-copy and channel-variant versions and snapshots the latest approved Brand Kit and the versioned channel capability catalog; existing versions remain compatible with a null capability snapshot. Approval fingerprints bind any capability snapshot stored on a content version. The copy editor can request an unsaved AI suggestion using the campaign brief and approved Brand Kit; it returns three distinct channel-copy options, lets the user compare and select one, and saves only the chosen text into a new immutable version. It requires server-side `OPENAI_API_KEY` and `OPENAI_MODEL` configuration; the three alternatives are not stored separately on the post. A user can request an advisory AI review of the exact saved content version; findings compare claims and style with that version's approved Brand Kit snapshot, and never approve or publish. This requires `OPENAI_API_KEY` and `OPENAI_MODEL`; live provider calls still need credentialed homologation. A PostgreSQL-backed media queue generates AI images, local text cards, or a grouped three-page static carousel for a saved content version; outputs go to private S3, are normalized and bounded, and require separate authorized media review, with carousel approval atomic across its pages. Carousel pages have editable copy before enqueue and channel-specific export presets; text cards now use those dimensions too and scale their layout to avoid clipping across aspect ratios. The Instagram publisher converts approved assets to JPEG and enforces its supported aspect ratio, width, and size constraints. Presets were checked against official Meta Instagram, TikTok photo, and LinkedIn image references; only Instagram image publishing is enabled, and remaining platform formats need validation before image connectors are enabled. `compose.dev.yaml` provides PostgreSQL, LocalStack, migration/bucket initialization, a verified local demo owner, web, and an opt-in media worker in Docker. Production worker scheduling remains separate.
- Brand Kits have tenant-and-brand-scoped immutable versions, source URL references, draft/approved/superseded states, manager-only editing/approval, and a version history. The private S3-compatible media slice is implemented for PNG/JPEG/WebP logos and visual template references with source/license/rights-expiry metadata and human review; temporary upload keys are isolated from verified final objects. LocalStack upload and replay-protection tests pass. A bounded cleanup job removes abandoned staging uploads after 24 hours; production scheduling, bucket/role/CORS configuration and editable template import remain future slices. See `docs/SOCIAL_CONNECTIONS.md` and `docs/PRODUCT_BACKLOG.md` for current integration status.
- Competitor research is a dedicated workspace destination with competitor-only observations, profile validation, public sites, feeds, and analysis; the selected brand is only an organization context and is not blended into the result data. YouTube channels can be looked up through the official API using the brand's connected YouTube account, previewed, and added through their official Atom feed URL. Instagram professional profiles can be previewed through Meta Business Discovery and monitored through the existing PostgreSQL worker when the brand has a connected Facebook Page linked to Instagram and the Meta app has approved `instagram_basic`; old Facebook connections need reauthorization to grant the new scope. Facebook Pages can be previewed and monitored through the Graph API using the brand's connected Page token; public competitor data requires Meta Page Public Content Access or Page Public Metadata Access approval. X profiles can be validated and monitored through official X API v2 after an X account with `users.read` and `tweet.read` is connected; this feature is disabled unless `X_COMPETITOR_RESEARCH_ENABLED=true` because X API use is pay-per-use. LinkedIn's organization-post permission only grants reads on pages where the connected member has an eligible administrative role, so it cannot monitor arbitrary competitor pages; the UI explains this boundary. The worker also supports authorized HTTPS RSS/Atom feeds and conservative same-origin sitemap monitoring for public websites, respecting robots.txt without executing JavaScript. It stores bounded observations with source links and capture timestamps, then optionally classifies themes and generates bilingual editorial ideas through the configured OpenAI model with storage disabled. Only bounded titles/summaries and brand name/industry are sent; source URLs remain local for citations. Suggestions remain advisory. Monitoring includes a heartbeat, bounded per-source run history, collection error categories, analysis coverage, manual retry, operational source summaries, 30-day topic comparisons with evidence links, and in-app alerts for collection failures, stale sources, and new observations. Alerts remain dashboard-only; external notification channels are not implemented. Additional engagement measures and source discovery remain pending. Use `docs/COMPETITOR_RESEARCH.md` for runtime and security limits.
