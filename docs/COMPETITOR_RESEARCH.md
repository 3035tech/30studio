# Competitor research

The first collector supports public RSS 2.0 and Atom feeds that a tenant is authorized to use. Up to 25 sources can be configured for a brand. Sources and observations are scoped to an organization and brand. The source URL and item link are retained as provenance; each observation records its capture time and retrieval method.

The worker rejects non-HTTPS feeds, credentials, query parameters, redirects, private or reserved DNS results, unsupported content types, external XML entities, oversized responses, and requests that exceed the timeout. It pins the HTTP connection to a validated DNS address, keeps TLS hostname verification enabled, and does not fetch links found inside feed entries. Feed text is untrusted metadata, never instructions, and is never given to tools. When the configured OpenAI model is available, up to ten bounded public titles and summaries plus the brand name and industry are sent with storage disabled for classification and bilingual idea generation. Source URLs are retained locally for citation and are not included in the model prompt.

Feed observations contain title, an optional plain-text summary, source link, and source publication date when available. The analysis worker assigns a controlled topic, summarizes the observed pattern, and suggests an original editorial angle. Results are stored with the source observation and shown with a citation link. Provider failures retry up to three times; unavailable analyses can be retried by a permitted user. Feed monitoring shows a source health state, last/next check time, consecutive failure count, localized error category, and up to eight recent collection runs per source. The database retains at most 50 runs per source. Authorized managers can queue an immediate check when an active source is failing or stale. The worker heartbeat is considered stale after 90 seconds. The dashboard summarizes analyzed, pending, and unavailable observations.

Per-brand in-app alert thresholds default to three consecutive failures and 36 hours since the last successful check. Managers can change them within 1–10 failures and 6–336 hours or disable alerts. Alerts are evaluated when the dashboard data is loaded and appear there; no email, push, or external notification is sent. Resuming an inactive source clears its failure count. These analyses are advisory suggestions, not verified claims. Engagement counts, source discovery, and non-RSS platforms are not implemented. The `metadata_only` data-quality value makes this coverage limit explicit.

`fast-xml-parser` is used for bounded RSS/Atom parsing. It is MIT licensed and runs only in the worker/server path, so it does not add browser bundle weight. The worker polls PostgreSQL using row locks with `SKIP LOCKED`, persists observations idempotently, applies conditional requests, and retries failed sources with bounded backoff. Run it with `npm run worker:competitors` or the opt-in Docker Compose `competitors` profile. Set `OPENAI_API_KEY` and `OPENAI_MODEL` to enable AI analysis; collection still runs without them. Migration `0030` adds collection history, alert settings, and the worker heartbeat. It is additive; an older app version can ignore those tables, so rollback should revert the application without dropping monitoring data.
